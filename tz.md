# «Рабочий планировщик» — подробное техническое задание MVP

**Версия документа:** 1.1  
**Дата:** 18.08.2026  
**Статус:** готово к реализации  
**Целевая папка проекта:** `D:\0 кодекс\Planer work`  
**Целевой браузер:** Google Chrome  
**Целевой формат публикации:** статический сайт GitHub Pages, публикация выполняется последним отдельным этапом

## 1. Назначение продукта

«Рабочий планировщик» — однопользовательское браузерное приложение для планирования клиентских задач по дням календарного месяца.

Пользователь должен иметь возможность:

- видеть месяц целиком с разбивкой на недели и дни;
- создавать задачи для одной или нескольких организаций;
- хранить задачи без назначенной даты в блокноте;
- назначать задачу на конкретный день в пределах ближайших 30 дней;
- отмечать выполнение галочкой;
- редактировать, копировать, переносить, упорядочивать и удалять задачи;
- искать задачи по описанию;
- фильтровать задачи по одной организации и по состоянию выполнения;
- автоматически переносить просроченные невыполненные задачи на текущий день;
- сохранять все рабочие данные локально в браузере без сервера и базы данных.

## 2. Границы MVP и дальнейшее развитие

В MVP работает один локальный пользователь. Регистрация, авторизация, пароли, сервер, база данных и синхронизация между устройствами отсутствуют.

Данные находятся только в `localStorage` того профиля Chrome и того адреса страницы, где открыт планировщик.

В будущем приложение может быть расширено до многопользовательской версии с доступом организаций по паролю, но эта логика и элементы такого интерфейса в MVP не реализуются. Организации и задачи получают стабильные уникальные идентификаторы.

## 3. Пользователь и права

**Локальный владелец** — человек, открывший приложение в поддерживаемом профиле Chrome.

В MVP этот пользователь имеет доступ ко всем функциям планировщика и ко всем локально сохранённым задачам. Других ролей и проверок прав нет.

## 4. Термины

- **Календарная задача** — задача с конкретной датой.
- **Задача блокнота** — обычная задача без назначенной даты.
- **Блокнот** — список задач без назначенной даты.
- **Общая задача** — одна задача, связанная с двумя–пятью организациями, имеющая общие дату, описание и галочку выполнения.
- **Автоперенос** — автоматическое перемещение просроченной задачи без галочки на текущий день.
- **Рабочий день** — выбранный календарный день и его всплывающее окно со списком задач.
- **Полная карточка** — раскрытое представление одной задачи со всеми действиями.

## 5. Состав проекта и ограничения файлов

Исполняемая часть приложения состоит ровно из трёх файлов:

1. `index.html` — семантическая структура страницы.
2. `styles.css` — вся визуальная часть и адаптивность.
3. `app.js` — состояние, бизнес-правила, календарь, интерфейс и `localStorage`.

Документы `tz.md`, файл цветового примера и возможная документация не считаются исполняемыми файлами приложения.

Требования:

- все рабочие файлы создаются только в `D:\0 кодекс\Planer work`;
- не создавать рабочую копию приложения в другой папке;
- использовать UTF-8;
- не использовать фреймворки, сборщики, серверные компоненты и внешнюю базу данных;
- не использовать абсолютные локальные пути в HTML, CSS или JavaScript;
- подключать `styles.css` и `app.js` относительными путями;
- не использовать JavaScript-модули, требующие HTTP-сервера для прямого открытия файла;
- приложение должно запускаться двойным щелчком по `index.html` в Chrome и как статическая страница GitHub Pages;
- временные тестовые файлы при разработке разрешены, но перед сдачей должны быть удалены или вынесены из итогового набора исполняемых файлов.

## 6. Целевая среда и адаптивность

### 6.1. Основной режим

- Google Chrome актуальной версии.
- Минимальное целевое разрешение: `1366×768`.
- Основной масштаб браузера: `100%`.
- Интерфейс на русском языке.
- Неделя начинается с понедельника.
- Даты отображаются в коротком формате `ДД.ММ.ГГ`.
- Названия месяцев и дней недели выводятся по русской локали.

### 6.2. Правило одного экрана

При `1366×768` и масштабе `100%` документ не имеет вертикальной или горизонтальной прокрутки. Основной календарь целиком помещается в область браузера.

Внутренняя прокрутка разрешена только:

- в списке задач выбранного дня;
- в блокноте;
- в форме или диалоге при увеличенном масштабе;
- в календарной области при экстремальном увеличении, когда иначе элементы стали бы нечитаемыми.

### 6.3. Поведение при увеличении масштаба

Интерфейс должен адаптироваться, а не обрезаться:

- при уменьшении доступной ширины верхняя панель может переходить на две строки;
- сначала сокращаются декоративные отступы;
- затем в ячейке дня уменьшается количество показанных названий организаций с трёх до одного;
- при ещё меньшей ширине в ячейке остаются только число и общий счётчик задач;
- календарь сохраняет семь колонок;
- размер кликабельных элементов не должен становиться меньше 32×32 px;
- текст не перекрывает соседние элементы;
- вся функция остаётся доступной через всплывающее окно дня.

Контрольные режимы проверки: `1366×768` при 100%, 125% и 150%, а также `1920×1080` при 100%.

## 7. Компоновка основного экрана

Экран состоит из четырёх зон.

### 7.1. Верхняя панель

Содержит:

- название **«Рабочий планировщик»**;
- кнопку перехода к предыдущему месяцу;
- название открытого месяца и года;
- кнопку перехода к следующему месяцу;
- кнопку **«Сегодня»**;
- кнопку **«Создать новую задачу»**;
- кнопку **«Блокнот»** без числового счётчика.

### 7.2. Панель поиска и фильтров

Содержит:

- строку поиска по описанию;
- один выпадающий фильтр организации;
- переключатель выполнения: «Все», `☐`, `☑`;
- кнопку **«Сбросить»**.

### 7.3. Строка дней недели

Порядок: Пн, Вт, Ср, Чт, Пт, Сб, Вс.

### 7.4. Сетка месяца

- Всегда используется сетка из семи колонок и шести строк, чтобы высота интерфейса не менялась между месяцами.
- В ячейках, относящихся к предыдущему или следующему месяцу, дата не показывается. Эти ячейки пустые и неактивные.
- Отображение соседних дат оставлено на будущую визуальную доработку и в MVP не реализуется.
- Текущий день выделяется зелёной рамкой.
- Выбранный день имеет отдельное визуальное состояние.

## 8. Содержимое ячейки дня

В ячейке показываются:

1. число месяца;
2. один общий счётчик подходящих задач;
3. первые три уникальных названия организаций из подходящих задач при достаточном месте;
4. при нехватке места — два, одно или ни одного названия согласно адаптивным правилам.

Счётчик включает одновременно выполненные и невыполненные задачи. Раздельные счётчики не реализуются в MVP.

Если действует поиск или фильтр, счётчик и названия отражают только отфильтрованные задачи.

Для общей задачи организации участвуют в списке уникальных названий по отдельности. Дубли одинакового названия в одной ячейке не показываются.

Нажатие на активную ячейку открывает всплывающее окно рабочего дня.

## 9. Всплывающее окно рабочего дня

Окно открывается поверх календаря. Календарь остаётся видимым под затемнением.

Окно содержит:

- выбранную дату;
- кнопку **«Создать задачу»**;
- список задач дня;
- крестик `×` закрытия.

Правила:

- длинный список прокручивается внутри окна;
- нажатие на затемнённый фон не закрывает окно;
- крестик закрывает окно;
- `Esc` допускается только как стандартное доступное закрытие диалога, но не рекламируется как горячая клавиша;
- при закрытии фокус возвращается в ячейку дня, из которой окно было открыто;
- при переходе к другому месяцу окно автоматически закрывается;
- одновременно раскрыта только одна полная карточка задачи;
- интерактивная галочка выполнения и кнопки действий находятся в полной карточке;
- свёрнутая строка показывает заголовок, краткий фрагмент описания, визуальное состояние галочки и служебные значки, но не меняет данные одним нажатием.

## 10. Модель организаций

Организация вводится свободным текстом.

Правила ввода:

- пользователь вводит название и нажимает `Enter`;
- название превращается в отдельную метку;
- одну метку можно удалить крестиком до сохранения;
- в календарной задаче разрешено от одной до пяти организаций;
- в задаче блокнота разрешено от нуля до пяти организаций;
- длина одного названия — от 1 до 100 символов после удаления пробелов по краям;
- последовательности внутренних пробелов сокращаются до одного пробела;
- одинаковые названия без учёта регистра не добавляются повторно;
- при вводе показываются подсказки из ранее сохранённых организаций;
- выбор подсказки выполняет то же действие, что и `Enter`;
- автоматически найденная организация повторно использует существующий идентификатор.

Внутренне организация содержит:

| Поле | Тип | Требование |
| --- | --- | --- |
| `id` | строка UUID | уникально и неизменно |
| `name` | строка | исходное отображаемое название |
| `normalizedName` | строка | имя для сравнения без регистра и лишних пробелов |
| `createdAt` | ISO-дата-время | техническое поле |
| `updatedAt` | ISO-дата-время | техническое поле |

Отдельный экран справочника организаций в MVP отсутствует.

## 11. Единая модель задачи

| Поле | Тип | Правило |
| --- | --- | --- |
| `id` | строка UUID | уникальный идентификатор |
| `organizationIds` | массив строк | 1–5 для календарной задачи, 0–5 для задачи блокнота |
| `date` | строка `YYYY-MM-DD` или `null` | дата календарной задачи; `null` означает блокнот |
| `description` | строка | от 1 до 3000 символов |
| `completed` | boolean | `false` при создании и всегда `false` в блокноте |
| `order` | целое число или `null` | позиция внутри своей группы дня; `null` в блокноте |
| `edited` | boolean | признак сохранённого редактирования |
| `autoCarried` | boolean | текущая отметка автопереноса, не история |
| `createdAt` | ISO-дата-время | техническое поле |
| `updatedAt` | ISO-дата-время | техническое поле |

Описание хранится как обычный многострочный текст:

- переносы строк сохраняются;
- HTML не интерпретируется;
- текст выводится только безопасным способом, эквивалентным `textContent`;
- ссылки остаются обычным текстом и автоматически не активируются;
- вставка из буфера и голосовой ввод разрешены;
- пробелы по краям удаляются при сохранении;
- пустое после удаления пробелов описание недопустимо.

### 11.1. Заголовок карточки

- Одна организация: показывается её название.
- Две–пять организаций: показывается **«Общая задача · N»**, где `N` — число организаций.
- Под заголовком общей задачи выводятся все связанные организации компактными метками.

Общая задача имеет единые дату, описание, положение и галочку выполнения для всех организаций.

## 12. Состояние задачи в блокноте

Блокнот не является отдельной моделью данных. В нём отображаются задачи из общего массива `tasks`, у которых `date = null`.

Для задачи блокнота действуют правила:

- `completed = false` и галочка не показывается;
- `order = null`;
- `autoCarried = false` и отметка переноса не показывается;
- при назначении даты меняется существующая задача с тем же `id`, после чего она исчезает из блокнота и появляется в календаре;
- если исходную задачу требуется оставить в блокноте для повторного использования, пользователь сначала создаёт её копию и назначает дату копии.

Заголовок задачи блокнота:

- без организации — **«Без организации»**;
- одна организация — название организации;
- несколько — **«Общая задача · N»**.

Задачи блокнота сортируются по `updatedAt` от новых к старым. Кнопки `↑` и `↓` в блокноте отсутствуют.

## 13. Единое локальное состояние

Используется один ключ:

`workPlanner.state.v1`

Значение — JSON-объект со следующими разделами:

| Раздел | Содержимое |
| --- | --- |
| `version` | число `1` |
| `organizations` | массив организаций |
| `tasks` | единый массив календарных задач и задач блокнота |

Преимущество одного корневого объекта — согласованное сохранение задач и связанных организаций одной операцией.

Фильтры, поисковая строка, открытый месяц, открытые окна и временные формы не сохраняются. После перезагрузки:

- открывается текущий месяц;
- фильтры сброшены;
- строка поиска пустая;
- всплывающие окна закрыты.

## 14. Создание задачи из выбранного дня

### Предусловия

- Пользователь открыл допустимый день.
- Создавать задачи в прошедшем дне нельзя.
- Допустимая новая дата — от текущего дня до `текущий день + 30 календарных дней` включительно.

### Шаги

1. Пользователь нажимает **«Создать задачу»**.
2. Открывается форма с датой выбранного дня.
3. Пользователь добавляет 1–5 организаций.
4. Пользователь вводит описание.
5. Пользователь сохраняет задачу.

### Альтернативный путь

Пользователь очищает дату. Форма переходит в режим сохранения задачи в блокноте:

- организация становится необязательной;
- описание остаётся обязательным;
- после сохранения запись появляется в блокноте, а не в календаре.

### Результат

- Календарная задача получает пустую галочку.
- Новая задача размещается первой в группе невыполненных задач выбранного дня.
- Форма закрывается.
- Появляется уведомление **«Задача создана»**.

## 15. Общая кнопка «Создать новую задачу»

При нажатии открывается форма с начальными значениями:

- дата — «Без даты»;
- организации — пусто;
- описание — пусто;
- режим назначения — блокнот.

Если пользователь сохраняет форму без даты, создаётся задача блокнота с `date = null`. Организации при этом необязательны.

Если пользователь выбирает дату, форма превращается в календарную задачу:

- требуется хотя бы одна организация;
- дата должна входить в диапазон сегодня…сегодня + 30 дней;
- после сохранения задача размещается в начале выбранного дня.

## 16. Работа с блокнотом

### 16.1. Открытие

Кнопка **«Блокнот»** открывает поверх календаря панель со списком задач без даты. Число задач на кнопке не показывается.

### 16.2. Действия с задачей блокнота

Доступны:

- открыть;
- редактировать;
- копировать;
- удалить;
- назначить дату.

### 16.3. Назначение даты задаче блокнота

1. Пользователь нажимает **«Назначить дату»**.
2. Открывается календарик на диапазон сегодня…сегодня + 30 дней.
3. Если в задаче нет организации, пользователь обязан добавить 1–5 организаций.
4. Пользователь выбирает дату.
5. У существующей задачи устанавливается выбранная дата; её `id` и остальные данные сохраняются.
6. Задача получает пустую галочку, исчезает из блокнота и помещается в начало невыполненных задач выбранного дня.
7. Показывается уведомление **«Задача добавлена в календарь»**.

### 16.4. Перемещение календарной задачи в блокнот

У невыполненной календарной задачи доступна кнопка **«В блокнот»**.

После подтверждения:

- у существующей задачи устанавливается `date = null`;
- задача исчезает из календарного дня и появляется в блокноте;
- организации и описание сохраняются;
- `completed = false`, `order = null`, `autoCarried = false`;
- показывается уведомление **«Задача перемещена в блокнот»**.

Для выполненной задачи кнопка **«В блокнот»** не показывается. Для повторного использования выполненной задачи применяется копирование.

## 17. Просмотр полной карточки

Нажатие на строку задачи раскрывает её внутри окна дня.

Полная карточка показывает:

- заголовок;
- список организаций;
- дату;
- полное описание;
- чекбокс выполнения;
- отметку `★`, если задача ранее редактировалась;
- отметку `↷ перенесено`, если задача автоматически перенесена и отметка ещё активна;
- кнопки `↑`, `↓`, **«Редактировать»**, **«Перенести»**, **«В блокнот»**, **«Копировать»**, **«Удалить»** с учётом доступности действия.

## 18. Редактирование

Редактировать можно организации, описание и дату невыполненной задачи. Дату можно изменить только в пределах от текущего дня до текущего дня + 30 календарных дней включительно; очистка даты переводит задачу в блокнот.

Во время редактирования:

- карточка получает зелёную акцентную рамку;
- показывается подпись **«Редактирование»**;
- остальные конфликтующие действия блокируются.

После сохранения:

- устанавливается `edited = true`;
- рядом с заголовком постоянно показывается золотая `★`;
- `updatedAt` обновляется;
- автопереносная отметка очищается, поскольку пользователь осознанно обработал задачу;
- показывается уведомление **«Изменения сохранены»**.

Перенос, изменение порядка, установка галочки и автоматический перенос сами по себе не устанавливают `edited`.

Если пользователь закрывает форму с несохранёнными изменениями, показывается диалог **«Есть несохранённые изменения»** с кнопками:

- **«Сохранить»**;
- **«Не сохранять»**;
- **«Отмена»**.

## 19. Галочка выполнения

### 19.1. Установка галочки

- Интерактивный чекбокс находится в полной карточке.
- Установка сохраняется немедленно.
- Задача становится выполненной и визуально приглушённой.
- Задача автоматически перемещается в конец группы выполненных задач этого дня.
- Кнопки **«Перенести»** и **«В блокнот»** скрываются.
- Кнопки **«Копировать»**, **«Редактировать»** и **«Удалить»** остаются; изменение даты выполненной задачи через редактирование запрещено.
- Активная отметка автопереноса очищается.

### 19.2. Снятие галочки

Снять галочку разрешено.

- Если дата задачи сегодня или в будущем, задача становится первой в группе невыполненных этого дня.
- Если дата уже прошла, задача немедленно переносится на текущий день, становится первой среди невыполненных и получает отметку автопереноса.

### 19.3. Текстовое отображение

В карточке не показываются подписи «Сделано» и «Не сделано». Состояние передаётся формой чекбокса, приглушением карточки и доступной подписью для экранных средств.

## 20. Ручной перенос

Кнопка **«Перенести»** доступна только у невыполненной календарной задачи.

Правила:

- диапазон — от сегодняшнего дня до сегодняшнего дня + 30 календарных дней включительно;
- прошедшие даты недоступны;
- даты дальше диапазона недоступны;
- текущая дата самой задачи недоступна как бессмысленный выбор;
- выполненная задача напрямую не переносится;
- после переноса старое место не запоминается;
- задача помещается первой среди невыполненных целевого дня;
- ручной перенос не получает специальной долговременной цветовой отметки;
- `autoCarried` очищается;
- показывается уведомление **«Задача перенесена»**.

Чтобы повторить выполненную задачу в другом дне, пользователь нажимает **«Копировать»**, получает невыполненную копию и назначает ей новую дату. Исходная выполненная задача остаётся в прежнем дне.

## 21. Автоматический перенос

Проверка выполняется:

- при первой загрузке страницы;
- при возвращении видимости вкладке;
- при получении окном фокуса после смены календарной даты.

Алгоритм:

1. Определить локальную сегодняшнюю дату без времени суток.
2. Найти все календарные задачи с `completed = false` и датой раньше сегодняшней.
3. Отсортировать переносимые задачи по старой дате от более ранней к более поздней, затем по старому порядку.
4. Перенести их непосредственно на текущий день, пропуская промежуточные даты.
5. Разместить перенесённый блок в начале невыполненной части текущего дня, сохранив порядок шага 3.
6. Установить `autoCarried = true`.
7. Сохранить состояние одним обновлением `localStorage`.

Выполненные задачи и задачи блокнота с `date = null` не переносятся.

Отметка автопереноса:

- переживает перезагрузку, чтобы перенос был заметен;
- не является историей и не хранит старую дату;
- очищается после редактирования, ручного переноса или выполнения;
- не переносится в копию или задачу блокнота.

## 22. Копирование

Кнопка **«Копировать»** доступна для календарной задачи и задачи блокнота.

### 22.1. Копия календарной задачи

- форма открывается с теми же организациями, описанием и датой;
- галочка всегда пустая;
- `edited = false`;
- `autoCarried = false`;
- пользователь может изменить дату или очистить её для сохранения в блокнот;
- оригинал не изменяется.

Если оригинал невыполненный и копия сохранена в тот же день, копия размещается сразу после оригинала. Если оригинал выполненный, невыполненная копия размещается в начале невыполненной группы, поскольку выполненные всегда находятся ниже.

### 22.2. Копия задачи блокнота

- создаётся новая независимая задача с новым `id` и `date = null`;
- организации и описание заранее заполнены;
- после сохранения копия становится первой в блокноте;
- `completed = false`, `edited = false`, `autoCarried = false`;
- оригинал не изменяется.

## 23. Удаление

Удаление необратимо. Корзины и восстановления нет.

Перед удалением всегда показывается подтверждение:

- для одной организации — название организации;
- для общей задачи — текст **«Удалить общую задачу для N организаций?»**;
- для задачи блокнота без организации — текст **«Удалить задачу без организации?»**.

Кнопки подтверждения:

- **«Удалить»** — красная опасная кнопка;
- **«Отмена»**.

После удаления показывается уведомление **«Удалено»**.

Организация, которая больше не используется ни одной задачей, удаляется из внутреннего массива организаций и перестаёт предлагаться в автоподстановке.

## 24. Порядок задач внутри дня

Список всегда состоит из двух групп:

1. невыполненные;
2. выполненные.

Невыполненные всегда выше выполненных.

Правила размещения применяются последовательно, в порядке совершения действий:

- новая, получившая дату, вручную перенесённая или возвращённая из выполненных задача помещается первой среди невыполненных;
- автоматически перенесённые при одной проверке задачи помещаются одним блоком в начало невыполненных; более позднее действие пользователя может поместить другую задачу выше этого блока;
- копия невыполненной задачи в том же дне размещается сразу после оригинала как единственное исключение из правила начала списка;
- выполненная задача помещается последней среди выполненных;
- старое место при переносе не сохраняется.

Кнопки `↑` и `↓` показываются только в полной карточке и перемещают задачу внутри её текущей группы. Пересекать границу между невыполненными и выполненными кнопками порядка нельзя.

Для первой задачи группы кнопка `↑` выключена. Для последней задачи группы кнопка `↓` выключена.

Если активен поиск или хотя бы один фильтр, обе кнопки сортировки выключены и показывается подсказка **«Сбросьте поиск и фильтры, чтобы изменить порядок»**.

В блокноте ручной порядок отсутствует.

## 25. Поиск и фильтры

### 25.1. Поиск

- Поиск работает только по описанию.
- Названия организаций поиском не проверяются.
- Поиск выполняется сразу при вводе каждого символа.
- Сравнение выполняется без учёта регистра.
- Ищется вхождение последовательности символов, а не только целого слова.
- Пробелы по краям поискового запроса игнорируются.

### 25.2. Фильтр организации

- Можно выбрать только одну организацию.
- Список организаций сортируется по русскому алфавиту.
- Общая задача отображается, если выбранная организация входит в её массив.

### 25.3. Фильтр выполнения

Варианты:

- «Все»;
- `☐` — только невыполненные;
- `☑` — только выполненные.

У иконок есть доступные подписи для экранных средств.

### 25.4. Совместная работа

Условия объединяются логическим **И**:

`организация И выполнение И совпадение описания`.

### 25.5. Сброс

Кнопка **«Сбросить»**:

- очищает строку поиска;
- устанавливает организацию «Все»;
- устанавливает выполнение «Все»;
- немедленно восстанавливает полный календарный список.

Фильтры не сохраняются после перезагрузки.

### 25.6. Блокнот

В блокноте применяются поиск по описанию и фильтр организации. Фильтр выполнения не применяется, поскольку у задач без даты галочка не показывается и `completed` всегда равно `false`.

## 26. Навигация по месяцам и допустимые даты

- При запуске открыт текущий месяц.
- Кнопки предыдущего и следующего месяца меняют месяц на один.
- Кнопка **«Сегодня»** возвращает текущий месяц и визуально выделяет сегодняшний день.
- Пользователь может просматривать прошлые месяцы с выполненными задачами.
- Вперёд можно просматривать календарь без ограничения, но создавать, планировать и переносить задачи разрешено только в диапазоне сегодня…сегодня + 30 дней.
- В прошедшем дне кнопка создания календарной задачи выключена; день остаётся доступным для просмотра истории выполненных задач.
- Открытое окно дня закрывается при смене месяца.

Все бизнес-даты хранятся как `YYYY-MM-DD` и сравниваются как локальные календарные даты. Для них нельзя применять преобразование, способное сдвинуть дату из-за UTC или часового пояса.

## 27. Уведомления и диалоги

Краткие уведомления показываются внизу экрана поверх интерфейса и исчезают через 3 секунды.

Требуемые уведомления:

- «Задача создана»;
- «Задача сохранена в блокноте»;
- «Изменения сохранены»;
- «Задача перенесена»;
- «Задача добавлена в календарь»;
- «Задача перемещена в блокнот»;
- «Копия создана»;
- «Удалено»;
- «Не удалось сохранить данные».

Уведомления не должны блокировать дальнейшую работу.

Подтверждающие диалоги блокируют фон и получают клавиатурный фокус.

## 30. Доступность и управление

- Все действия доступны через `Tab` и `Shift+Tab`.
- `Enter` активирует обычные кнопки.
- `Space` переключает чекбокс.
- Стрелки клавиатуры разрешено использовать для перемещения фокуса по календарной сетке как стандартное поведение компонента.
- Специальные пользовательские горячие клавиши не реализуются.
- Каждый интерактивный значок имеет текстовое доступное имя.
- Цвет не является единственным признаком состояния.
- Фокус имеет заметную зелёную рамку.
- При открытом диалоге фокус не уходит в фон.
- После закрытия фокус возвращается на вызвавший элемент.
- Крестик имеет доступное имя **«Закрыть»**.
- Чекбокс имеет доступное имя с заголовком задачи, например **«Выполнено: Ромашка»**.
- Уважать `prefers-reduced-motion`: отключить необязательные анимации.

## 31. Сохранение, ошибки и целостность

### 31.1. Когда сохранять

Сохранять после каждого подтверждённого изменения:

- создание;
- редактирование;
- изменение галочки;
- перенос;
- автоперенос;
- изменение порядка;
- копирование;
- перемещение в блокнот;
- назначение даты задаче блокнота;
- удаление.

Интерфейс не должен показывать успешное уведомление до успешной записи `localStorage`.

### 31.2. Ошибка записи

Если запись не удалась:

- показать уведомление **«Не удалось сохранить данные»**;
- оставить форму открытой;
- не удалять введённый пользователем текст;
- не показывать действие как завершённое;
- вывести техническую причину в консоль без содержимого пользовательских задач.

### 31.3. Повреждённый JSON

Если `workPlanner.state.v1` нельзя прочитать:

- не перезаписывать и не удалять значение автоматически;
- показать блокирующее сообщение **«Данные планировщика повреждены и не были изменены»**;
- заблокировать операции записи;
- предложить кнопку **«Повторить чтение»**;
- предложить кнопку **«Очистить локальные данные»**;
- очистка требует отдельного подтверждения **«Удалить повреждённые локальные данные без возможности восстановления?»**;
- после подтверждения удалить только ключ `workPlanner.state.v1` и создать пустое состояние.

### 31.4. Несколько вкладок

MVP рассчитан на одну открытую вкладку. Межвкладочная синхронизация не реализуется. Пользователь должен работать только в одной вкладке, иначе последнее сохранение может заменить изменения другой вкладки.

## 32. Пустое состояние

Демонстрационные задачи не создаются.

При первом запуске показывается пустой календарь и короткая подсказка:

**«Выберите день или создайте задачу в блокноте»**.

В пустом блокноте:

**«Здесь будут задачи без назначенной даты»**.

При пустом результате фильтра:

**«Задачи не найдены»** и кнопка **«Сбросить»**.

## 33. Безопасность и конфиденциальность

- Не использовать `innerHTML` для пользовательских организаций и описаний.
- Не выполнять пользовательский текст как HTML или JavaScript.
- Не помещать описания и организации в URL.
- Не отправлять данные в сеть.
- Не использовать аналитику, трекеры и сторонние API.
- Не сохранять пароли, токены или секреты.
- Не записывать пользовательские описания в консоль.
- В Git-репозиторий попадают только код и документация, но не содержимое `localStorage`.
- Публикация кода на GitHub не публикует локальные задачи.

## 34. Производительность

Нормативный объём проверки:

- до 200 календарных задач в одном месяце;
- типовой максимум до 10 задач в одном дне;
- до 200 задач без даты в блокноте;
- до 5 организаций в одной задаче;
- описание до 3000 символов.

При этом:

- ввод в поиск должен визуально обновлять результат без заметной задержки;
- переключение месяца должно занимать менее 200 мс на целевом компьютере после загрузки;
- операции `localStorage` не должны выполняться на каждый введённый символ описания, только при сохранении;
- не создавать повторных полных пересчётов внутри одного пользовательского действия;
- при изменении интерфейса избегать множественных последовательных перерисовок.

Метрика 200 мс должна быть фактически измерена в Chrome при приёмке, а не считаться выполненной без проверки.

## 35. Полный список сценариев использования

### UC-01. Первый запуск

**Актор:** локальный владелец.  
**Действие:** открывает `index.html`.  
**Результат:** текущий месяц, пустые фильтры, пустой календарь, подсказка, отсутствуют демонстрационные данные.

### UC-02. Просмотр другого месяца

**Актор:** локальный владелец.  
**Действие:** нажимает стрелку предыдущего или следующего месяца.  
**Результат:** сетка перестраивается, окно дня закрывается, фильтры текущей сессии продолжают действовать.

### UC-03. Возврат к сегодняшнему дню

**Действие:** нажимает **«Сегодня»**.  
**Результат:** открыт текущий месяц, текущий день выделен.

### UC-04. Просмотр дня

**Действие:** нажимает ячейку текущего месяца.  
**Результат:** открыто окно дня; список соответствует поиску и фильтрам; страница под окном не прокручивается.

### UC-05. Создание задачи из дня

**Действие:** открывает допустимый день, вводит организацию через `Enter`, описание и сохраняет.  
**Результат:** невыполненная задача первая в дне, данные сохранены, показано уведомление.

### UC-06. Создание общей задачи

**Действие:** добавляет 2–5 организаций и одно описание.  
**Результат:** одна карточка **«Общая задача · N»**, одна дата и одна галочка; карточка находится фильтром каждой организации.

### UC-07. Создание задачи без даты общей кнопкой

**Действие:** нажимает **«Создать новую задачу»**, оставляет дату пустой, вводит описание и при желании организации.  
**Результат:** создана задача блокнота с `date = null`; галочка не показывается.

### UC-08. Назначение даты задаче блокнота

**Действие:** открывает блокнот, выбирает задачу, нажимает **«Назначить дату»**, указывает организации при необходимости и дату.  
**Результат:** та же задача с тем же `id` исчезла из блокнота и появилась в выбранном дне календаря.

### UC-09. Повторное использование задачи через копирование

**Действие:** копирует задачу в блокноте, затем назначает дату копии.  
**Результат:** оригинал остаётся в блокноте, а независимая копия появляется в выбранном дне календаря.

### UC-10. Перемещение задачи в блокнот

**Действие:** у невыполненной задачи нажимает **«В блокнот»** и подтверждает.  
**Результат:** та же задача с тем же `id` исчезла из дня и появилась первой в блокноте с `date = null`.

### UC-11. Редактирование

**Действие:** меняет организации или описание и сохраняет.  
**Результат:** изменения записаны, появилась `★`, карточка сохраняет место, автопереносная отметка очищена.

### UC-12. Отмена несохранённых изменений

**Действие:** меняет поле и закрывает форму.  
**Результат:** показан выбор «Сохранить / Не сохранять / Отмена»; данные не теряются без решения пользователя.

### UC-13. Выполнение

**Действие:** устанавливает галочку.  
**Результат:** карточка приглушена, перемещена в конец выполненной группы, прямой перенос скрыт.

### UC-14. Возврат выполненной задачи в работу

**Действие:** снимает галочку.  
**Результат:** для сегодняшней/будущей даты задача первая среди невыполненных; для прошлой даты она переносится на сегодня и отмечается как автоперенесённая.

### UC-15. Ручной перенос

**Действие:** открывает невыполненную задачу, выбирает **«Перенести»** и допустимую дату.  
**Результат:** задача удалена из старого дня и стала первой среди невыполненных нового дня.

### UC-16. Повторение выполненной задачи

**Действие:** у выполненной задачи выбирает **«Копировать»**, задаёт новую дату и сохраняет.  
**Результат:** оригинал остаётся выполненным; создана независимая невыполненная задача.

### UC-17. Автоперенос после пропущенных дней

**Действие:** открывает приложение после нескольких дней отсутствия.  
**Результат:** все просроченные задачи без галочки сразу находятся в сегодняшнем дне, выделены как перенесённые; промежуточных копий нет.

### UC-18. Изменение порядка

**Действие:** без активных фильтров открывает задачу и нажимает `↑` или `↓`.  
**Результат:** порядок меняется только внутри группы выполнения и сохраняется после перезагрузки.

### UC-19. Попытка сортировки при фильтре

**Действие:** включает поиск или фильтр и открывает карточку.  
**Результат:** стрелки выключены, показана подсказка о сбросе фильтров.

### UC-20. Поиск по описанию

**Действие:** вводит фрагмент текста.  
**Результат:** календарь обновляется после каждого символа; названия организаций отдельно не ищутся.

### UC-21. Фильтр организации

**Действие:** выбирает одну организацию.  
**Результат:** остаются одиночные и общие задачи, связанные с выбранной организацией.

### UC-22. Комбинированная фильтрация

**Действие:** выбирает организацию, `☐` и вводит текст.  
**Результат:** показываются только записи, удовлетворяющие всем трём условиям.

### UC-23. Сброс фильтров

**Действие:** нажимает **«Сбросить»**.  
**Результат:** поиск пуст, фильтры «Все», показаны все задачи месяца.

### UC-24. Удаление одиночной задачи

**Действие:** нажимает **«Удалить»**, подтверждает.  
**Результат:** задача необратимо удалена, показано уведомление.

### UC-25. Удаление общей задачи

**Действие:** удаляет общую задачу.  
**Результат:** подтверждение содержит число организаций; удаляется одна общая карточка, а не несколько отдельных задач.

### UC-26. Голосовое заполнение описания

**Действие:** ставит курсор в описание и запускает системную диктовку HiDu или `Win + H`.  
**Результат:** продиктованный текст появляется как обычный текст, его можно отредактировать и сохранить; приложение не получает аудио.

### UC-27. Перезагрузка страницы

**Действие:** обновляет страницу.  
**Результат:** календарные задачи, задачи блокнота, галочки и порядок восстановлены; открыт текущий месяц; фильтры сброшены.

### UC-28. Повреждённое хранилище

**Действие:** приложение обнаруживает некорректный JSON.  
**Результат:** данные не перезаписаны; показана блокирующая ошибка и безопасные варианты повторить или подтвердить очистку.

### UC-29. Работа при увеличенном масштабе

**Действие:** увеличивает масштаб Chrome до 125% или 150%.  
**Результат:** элементы не перекрываются; организация в ячейке сокращается раньше функциональности; списки доступны через внутреннюю прокрутку.

### UC-30. Локальный и опубликованный запуск

**Действие:** открывает приложение локально и затем опубликованную копию GitHub Pages.  
**Результат:** функции интерфейса одинаковы; наборы `localStorage` независимы и автоматически не переносятся между адресами.

## 37. Критерии приёмки

Результат принимается только при фактической проверке каждого пункта.

1. В папке проекта находятся рабочие `index.html`, `styles.css`, `app.js` и документация; исполняемая часть не требует других файлов.
2. Прямое открытие `index.html` в Chrome не показывает ошибок в консоли.
3. Календарь правильно строит все месяцы, включая февраль високосного года, и начинает неделю с понедельника.
4. При `1366×768` и 100% нет прокрутки документа.
5. При 125% и 150% элементы не перекрываются, необходимые списки доступны.
6. В ячейке видны общий счётчик и до трёх организаций; завершённые и незавершённые входят в один счётчик.
7. Соседние даты другого месяца не показаны.
8. Кнопка «Сегодня» возвращает текущий месяц.
9. Создание из дня и общей кнопкой работает согласно разным начальным значениям.
10. Календарная задача требует 1–5 организаций; задача без даты в блокноте допускает 0–5.
11. Общая задача имеет одну карточку, одну галочку и находится фильтром каждой организации.
12. Описание хранит переносы строк, не исполняет HTML и ограничено 3000 символами.
13. При назначении даты задача исчезает из блокнота и с тем же `id` появляется в календаре.
14. Задачу можно переместить из календаря в блокнот.
15. Галочка немедленно перемещает задачу вниз; снятие возвращает вверх или на текущий день.
16. Выполненную задачу нельзя перенести напрямую, но можно скопировать.
17. Ручной перенос ограничен 30 днями.
18. Просроченные задачи автоматически переходят непосредственно на сегодня.
19. Автоперенос визуально отличается и не хранит старую дату.
20. Порядок стрелками сохраняется и отключён при поиске/фильтрах.
21. Поиск проверяет только описание и работает сразу.
22. Фильтры объединяются через «И» и сбрасываются одной кнопкой.
23. Удаление всегда требует подтверждения; восстановления нет.
24. Несохранённое редактирование нельзя потерять без выбора пользователя.
25. Все подтверждённые изменения восстанавливаются после перезагрузки.
26. Повреждённый JSON не удаляется автоматически.
27. В исходном коде нет пользовательских данных, токенов, паролей и сетевой отправки задач.
28. Поле описания принимает текст от системной диктовки как обычный ввод.
29. Локальная и GitHub Pages версии имеют одинаковую функциональность.
30. На тестовом объёме 200 задач месяц переключается не дольше 200 мс на целевом компьютере; результат измерения зафиксирован.

## 38. Минимальный набор ручных тестов

1. Создать одиночную задачу на сегодня.
2. Создать общую задачу для пяти организаций.
3. Проверить запрет шестой организации.
4. Создать в блокноте задачу без организации.
5. Назначить ей дату и убедиться, что она исчезла из блокнота и появилась в календаре с тем же `id`.
6. Отправить невыполненную задачу обратно в блокнот.
7. Выполнить задачу и проверить перемещение вниз.
8. Снять галочку у сегодняшней задачи и проверить перемещение вверх.
9. Снять галочку у выполненной задачи прошлого дня и проверить перенос на сегодня.
10. Проверить запрет прямого переноса выполненной задачи.
11. Скопировать выполненную задачу на новый день.
12. Проверить ручной перенос на сегодня + 30 и запрет сегодня + 31.
13. Смоделировать отсутствие несколько дней и проверить автоперенос.
14. Проверить `↑` и `↓` без фильтров.
15. Включить фильтр и проверить блокировку стрелок.
16. Проверить поиск по описанию и отсутствие поиска по организации.
17. Проверить общую задачу фильтром каждой организации.
18. Проверить удаление одиночной, общей задачи и задачи блокнота.
19. Проверить диалог несохранённых изменений всеми тремя кнопками.
20. Обновить страницу и сверить данные и порядок.
21. Подменить значение `localStorage` некорректным JSON и проверить неразрушающую ошибку.
22. Ввести описание через системную диктовку или `Win + H`.
23. Проверить `1366×768` при 100%, 125% и 150%.
24. Проверить клавиатурный фокус и закрытие крестиком.
25. Проверить локальный запуск и тестовую GitHub Pages публикацию перед финальным размещением.

## 39. Что не входит в MVP

- регистрация, вход и пароли;
- личные кабинеты организаций;
- сервер и база данных;
- синхронизация между устройствами и вкладками;
- совместное редактирование;
- разграничение прав;
- резервное копирование, экспорт и импорт;
- восстановление удалённых задач;
- история старых дат и версий описания;
- отдельная галочка для каждой организации общей задачи;
- раздельные счётчики выполненных и невыполненных задач в ячейке дня;
- показ соседних дат другого месяца;
- ручная сортировка задач блокнота;
- drag-and-drop задач;
- суммы, платежи и финансовые итоги;
- уведомления вне открытой страницы;
- собственная запись звука;
- прямой запуск или API-интеграция HiDu;
- автоматический перенос локальных данных между `file://` и GitHub Pages;
- мобильный интерфейс как основной сценарий.

## 40. Последовательность реализации

1. Создать семантический статический каркас и палитру.
2. Реализовать локальную модель данных и безопасное чтение/сохранение.
3. Реализовать календарные вычисления и сетку месяца.
4. Реализовать организации и формы создания.
5. Реализовать окно дня, карточки и галочку.
6. Реализовать порядок, перенос и автоперенос.
7. Реализовать блокнот для задач без даты.
8. Реализовать поиск и фильтры.
9. Реализовать ошибки, подтверждения, уведомления и доступность.
10. Провести ручные и автоматизированные проверки на нормативном объёме.
11. Удалить временные тестовые артефакты из итоговой поставки.
12. Показать локальный результат пользователю и получить подтверждение.
13. Только после подтверждения выполнить отдельный последний этап публикации на GitHub Pages.

Публикация на GitHub не является частью текущего этапа и не должна выполняться автоматически.
